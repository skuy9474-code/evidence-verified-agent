# 최종 결과 보고서

과제명: 모니터링 근거 대조를 통한 AI 장애 진단 답변 검증 개선

선택 과제: 1번 — 기존 Base AI Project 개선

최종 검수일: 2026년 10월 21일

저장소: https://github.com/skuy9474-code/skala-ai-mini-project

## 1. 문제와 목표

기존 Base AI Agent는 모니터링과 대응 매뉴얼을 조사해 장애 진단 답변을 작성한다. 기존 검사 조건은 답변 길이와 번호 포함 여부여서, CPU 수치나 시스템 상태가 틀려도 형식만 맞으면 통과할 수 있었다. 최대 재작성 후 강제 통과시키는 동작도 있었다.

이번 개선의 목표는 **같은 요청에서 조회한 시스템 상태·CPU·메모리와 AI 답변을 비교하고, 불일치하면 구체적인 피드백으로 다시 작성하며, 계속 실패하면 보류하는 것**이다. 예를 들어 조회한 CPU가 78%이고 답변이 18%이면 반려한다. 이 숫자는 설명용 예시다.

## 2. 주요 기능

- 자연어 장애 질문에서 조사 대상을 정하고 MCP Tool로 샘플 상태·CPU·메모리를 조회한다.
- MCP Resource에서 대응 매뉴얼을 조회한다.
- AI 답변을 근거·원인 가설·권장 조치·한계의 JSON 항목으로 받아 읽기 쉬운 문장으로 표시한다.
- 시스템별 상태·수치, 시스템 누락·중복·미조회 시스템 추가, 필수 항목을 검사한다.
- unknown은 0%가 아닌 미확인으로 안내한다.
- 본문에서 반복 인용한 CPU·메모리 및 명시적인 상태도 근거와 대조한다.
- 오류 피드백을 전달해 다시 작성하고, 총 3회 실패하면 검증 보류와 수집 근거를 제공한다.
- 검증 전 진단 초안을 숨기고 화면에 진행 단계·검사 사유·최종 결과를 표시한다.
- 모델·자료 연결 실패는 실행 오류로 안내하고, 검증 보류·검증 통과와 구분한다.

## 3. 개선 사항과 구현

| 개선 영역 | 기존 문제 | 개선 내용 |
|---|---|---|
| 검증 기준 | 길이·번호 중심 | 요청별 모니터링 원본과 시스템별 상태·수치 대조 |
| 대상 구분 | 미등록 시스템이 다른 기본 대상으로 바뀔 수 있음 | 지원하는 시스템명 형태를 보존하고 unknown으로 조회 |
| 답변 구성 | 모델이 제목·구분 기호를 바꾸면 검사 불안정 | JSON 항목 파싱 후 코드가 표시 형식만 담당 |
| 재작성 | 최대 시도 후 실패 초안도 통과 | 구체적 피드백, 총 3회 실패 후 보류 |
| 화면 | 검사 전 초안이 먼저 표시될 수 있음 | 내부에서 작성·검사하고 최종 진단만 표시 |
| 예외 처리 | 연결 오류가 응답 중단으로 보임 | HTTP 오류·SSE 오류 이벤트 및 사용자 안내 |

FastAPI는 요청과 결과 전달, LangGraph는 처리 흐름, MCP는 Tool·Resource·Prompt 조회를 담당한다. 독립 검증 모듈은 외부 모델을 호출하지 않는다. 로컬 생성 모델은 Ollama의 qwen3.5:2b이다. AI가 틀리게 쓴 수치를 원본으로 덮어쓰지 않고, 작성된 값을 그대로 검사한다.

## 4. 검증 결과

| 확인 항목 | 최종 결과 |
|---|---|
| 단위·그래프·ASGI 요청 경계 테스트 | 33개 통과 |
| 같은 합성 답변 23개 비교 | 오류 17개 중 기존 1개, 개선 17개 탐지 |
| 정확한 합성 답변 6개 | 기존 6개 통과, 개선 5개 통과·1개 보류 |
| 실제 모델·MCP·그래프 질문 6개 | 6개 규칙 검증 통과, 실행 오류 0개 |
| 실제 모델 평균 전체 처리 시간 | 10.265초, 평균 작성 1.0회 |
| 자연어·HTTP·SSE·일반 대화 최종 검수 | 6개 항목 모두 통과, 같은 에이전트 인스턴스 유지 |
| 별도 오류 주입 재작성 실험 | 첫 CPU 오류 반려 후 재작성, 2회째 통과 |

합성 답변 비교는 **같은 입력**을 두 검증기에 적용했다. 단일 답변 기준의 오류 탐지율은 기존 1/17, 개선 17/17이고, 정확한 답변 보류율은 기존 0/6, 개선 1/6이다. 개선본에서 보류된 1개는 내용이 맞지만 정형 형식에 맞지 않은 자유형 답변이다.

실제 모델의 6개 질문은 별도 자연 생성 통합 확인이다. 모델 초안에 의도적인 수치 오류를 넣지 않았다. 다만 교육용 MCP 클라이언트의 최초 1회 타임아웃 재시도 시뮬레이션과 연구 노드의 고정 지연이 전체 시간에 포함된다. 이 결과는 단일 기기·설정의 소규모 실험이며 운영 정확도나 환각 감소율이 아니다.

최종 코드로 다시 실행한 별도 통제 실험에서는 첫 초안의 CPU를 실험 코드로 바꾸어 실제 모델 재작성을 확인했다. 2회 작성, 17.149초였다. 자연 발생 오류율 평가와 섞지 않는다.

## 5. 최종 검수에서 발견하고 수정한 문제

1. 같은 줄에 현재 CPU 수치와 매뉴얼 임계 조건을 섞으면 잘못된 현재값도 예외 처리될 수 있었다. 각 수치 바로 뒤의 조건을 확인하고, 원문과 지표·수치·비교 조건이 일치할 때만 임계값으로 구분하도록 수정했다.
2. 근거 행은 degraded인데 본문에는 상태=healthy 또는 상태는 down이라고 쓰는 모순을 추가 검사했다. 대상이 불명확한 다중 시스템 상태도 보류한다.
3. 모델·MCP 처리 실패를 HTTP 503 또는 SSE Error로 안내하고, 실패한 처리를 성공 대화로 저장하지 않도록 했다. 내부 오류 상세는 응답에 내보내지 않는다.
4. 빈 질문·너무 긴 질문을 거절하고, 전송 중 Enter를 다시 눌렀을 때 중복 실행을 방지했다.
5. 설치 스크립트가 삭제된 옛 실행 파일을 안내하던 문제를 고치고, 고정 버전 의존성을 설치하도록 맞췄다.

## 6. 범위와 한계

- 검증 통과는 지정한 시스템·상태·CPU·메모리와 형식 규칙을 만족했다는 뜻이다. 원인 가설·권장 조치 전체의 의미적 정확성은 보증하지 않는다.
- 정규식이 지원하는 수치·상태 표현을 검사한다. 모든 자연어 표현이나 한글 수사를 이해하지 않는다.
- 등록된 이름과 -service 또는 web-01 같은 서버 번호 형태를 지원한다. 다른 이름·별칭이나 대상이 없는 질문은 auth-service로 조사될 수 있다. 화면에 표시된 조사 대상을 확인해야 한다.
- 매뉴얼 선택은 샘플 알림 키워드 기반이며, 여러 시스템의 모든 매뉴얼을 각각 검색·검증하는 RAG는 구현하지 않았다.
- 실제 서버 연결·자동 복구 조치는 구현하지 않았다. 샘플 수치를 사용하며 권장 조치를 자동 실행하지 않는다.
- 검증 전 초안을 숨기므로 최종 내용까지 대기 시간이 있고, 재작성 시 시간이 증가한다.
- OpenAI 백엔드 코드는 있으나 실제 API 호출·속도 비교는 검증하지 않았다. 이번 검수에서 외부 유료 AI API를 사용하지 않았다.
- 가상환경 설치를 새 컴퓨터에서 재현한 검수는 아니다. 기존 Python 3.11 가상환경으로 최종 소스를 실행했다.

## 7. 결론 및 추가 개선

Day1의 핵심 개선 목표 5개는 정한 범위에서 구현하고 확인했다. 형식만 보던 검사를 수집 근거 대조로 바꾸고, 실패 초안 강제 통과를 제거했다. 다음 개선에서는 다양한 자연어 표현과 시스템 별칭 지원, 시스템별 매뉴얼 검색, 더 큰 평가 세트, 필요 시 OpenAI 모델과의 동일 조건 비교를 진행할 수 있다.
