# 발표·시연 순서

## 1. 발표 시작 — 약 30초

제가 선택한 과제는 기존 Base AI Agent 개선입니다. 기존 프로그램은 답변의 길이와 번호를 검사하기 때문에, 형식만 맞으면 틀린 수치도 통과할 수 있었습니다. 그래서 조사한 자료와 AI 답변을 실제로 대조하도록 개선했습니다.

## 2. 실제 모델 시연 — 약 1분

실제 모델은 외부 API 키가 없는 로컬 Ollama qwen3.5:2b입니다. README의 실행 방법으로 서버를 준비하고 http://127.0.0.1:8610 에 접속합니다.

1. 화면 상단의 실제 모델 이름을 보여줍니다.
2. `auth-service 장애 원인을 진단해줘`를 입력합니다.
3. 자료 조사와 검증 단계, 시스템 상태·CPU·메모리, 최종 검증 카드를 보여줍니다.
4. `billing-service 응답이 느려요`를 입력해 unknown과 미확인 표시를 보여줍니다.

숫자는 조회할 때마다 샘플 변동이 있으므로 이전 시연 숫자를 외우지 않고, **같은 요청에서 조회한 값과 답변이 같은지** 설명합니다. 첫 응답이나 재작성은 더 오래 걸릴 수 있습니다.

## 3. 오류·재작성 시연 — 약 40초

실제 모델이 반드시 수치를 틀리게 쓰는 것은 아닙니다. 오류 경로는 별도 통제 실험으로 설명합니다.

- `python -m eval.rewrite_demo`: 첫 실제 모델 초안의 CPU를 실험 코드로 한 번 바꾸고, 반려와 실제 모델 재작성을 기록합니다. Ollama 실행이 필요합니다.
- 모델 없는 화면 시연은 별도 포트에서 `python sh/run_demo.py --backend fake --backend-port 8112 --frontend-port 8612`로 실행합니다. fake는 실제 AI 성능이 아닌 의도적인 오류 주입 시뮬레이션입니다. 화면 상단 표시를 함께 보여줍니다.
- 세 번 모두 실패하면 보류하는 동작은 `tests/test_graph.py` 및 `tests/test_api.py`의 AlwaysWrong 테스트로 증명합니다. 자연 생성 평가에서 발생했다고 말하지 않습니다.

## 4. 결과와 한계 — 약 40초

테스트 33개를 통과했고, 같은 합성 오류 답변 17개 중 기존 검증은 1개, 개선 검증은 17개를 걸러냈습니다. 정확한 자유형 답변 1개도 보류되어 형식 제약의 한계가 있습니다. 실제 로컬 모델 질문 6개는 지정한 규칙을 통과했습니다. 이는 작은 샘플 실험이며 운영 정확도나 환각 감소율이 아닙니다.

이번에는 시스템 상태와 CPU·메모리, 필수 항목을 검사했습니다. 원인과 조치 내용 전체가 옳다고 보장하지 않으며, 실제 운영 서버를 연결하거나 조치를 자동 실행하지 않았습니다.

## 예상 질문

**AI가 틀린 값을 쓰면 코드가 정답으로 바꾸나요?**

아닙니다. AI가 작성한 수치를 그대로 비교합니다. 틀리면 구체적인 피드백을 주고 AI가 다시 작성합니다. 코드는 JSON을 읽기 좋은 문장으로 표시합니다.

**검증 통과면 모든 내용이 맞나요?**

아닙니다. 정한 형식과 시스템 상태·수치 대조를 통과했다는 뜻입니다. 원인과 조치는 가설과 권장 사항입니다.

**왜 API 대신 Ollama를 사용했나요?**

현재 기기에 설치된 모델로 외부 유료 API 없이 기능을 확인할 수 있었기 때문입니다. API가 더 빠른지는 같은 조건의 비교가 필요하며 아직 측정하지 않았습니다.

**실제로 서버를 복구하나요?**

아닙니다. 샘플 데이터를 조회하고 점검 조치를 권장하는 도구입니다. 자동 복구 실행은 하지 않습니다.
